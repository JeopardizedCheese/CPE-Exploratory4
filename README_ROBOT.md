# ส่วนควบคุมหุ่น (robot_ctrl + teleop + robot_pose + target_lock)

| ไฟล์ | หน้าที่ |
| --- | --- |
| `firmware/robot_ctrl/` | ESP32: ล้อ, servo 2 ตัว, ระบบความปลอดภัยทั้งหมด (protocol v3, UDP 4211) |
| `teleop.py` | ขับด้วยคีย์บอร์ดจาก PC + บันทึกวิดีโอ/log ของทุก run ลง `runs/` |
| `fake_robot.py` | จำลอง firmware `robot_ctrl` บน PC ใช้ทดสอบ `teleop.py` โดยไม่ต้องมีหุ่น |
| `robot_pose.py` | หาตำแหน่ง/ทิศของหุ่นจาก AprilTag บนหลังคา เป็น mm บนสนาม |
| `target_lock.py` | ล็อกหินหนึ่งก้อนให้ planner ทำงานต่อจนเสร็จ แม้ vision จะกระพริบ |
| `tests/test_robot_pose.py`, `tests/test_target_lock.py` | เทสต์สังเคราะห์ |

`firmware/esp_link/` (ตัวรับเป้าหมายจาก vision พอร์ต 4210) ยังอยู่ แต่ในแบบปัจจุบันใช้แค่ดีบัก

## ภาพรวม: ใครทำอะไร

```
PC (โปรแกรม Python ตัวเดียว)
 ├─ กล้อง → vision.py        → หิน: สี, x, y, approach_deg
 ├─ กล้อง → robot_pose.py    → หุ่น: x, y, heading
 ├─ TargetLock               → เลือกหิน 1 ก้อนแล้วล็อกไว้
 ├─ planner (ยังไม่ได้เขียน)  → จะขับไปไหนต่อ
 └─ ส่ง UDP v3 20 ครั้ง/วินาที: drive l,r / grip
         ▼  Wi-Fi
ESP32 (robot_ctrl.ino)
 └─ หมุนมอเตอร์, ขยับ servo, หยุดเองเมื่อมีปัญหา
```

- การตัดสินใจทั้งหมด (เลือกก้อนไหน, เข้าทางไหน) **อยู่บน PC** ESP32 ไม่รู้จักหินหรือทิศทาง รู้แค่คำสั่งล้อและแขน
- ถ้า PC ค้างหรือ Wi-Fi หลุด ESP32 หยุดล้อเองภายใน 300 ms
- หุ่นเก็บได้ **ทีละก้อน** (แขนมี servo 2 ตัว) เป้าหมายคือทำให้แต่ละรอบสั้นและไม่พลาด
- **ไม่ใช้ HuskyLens** การยืนยันสีทำด้วยกล้องบนสนาม: ตัดสินสีก่อนเก็บ ถ้าไม่แน่ใจให้ข้าม

## 1. Firmware

1. Arduino IDE: ติดตั้ง board **esp32 by Espressif เวอร์ชัน 3.x** และ library **ArduinoJson 7**
2. `firmware/robot_ctrl/secrets.example.h` → คัดลอกเป็น `secrets.h` แล้วใส่ Wi-Fi
3. **แก้ `config.h` ให้ตรงกับสายที่ต่อจริงก่อน** (pin ทุกตัวในไฟล์เป็นค่าตัวอย่าง)
   - เลือกชนิด driver: `DRIVER_IN_IN_PWM` (TB6612/L298N) หรือ `DRIVER_TWO_PWM` (DRV8833/MX1508)
   - ปุ่มหยุดฉุกเฉินต่อระหว่าง `ESTOP_PIN` กับ GND
   - เริ่มที่ `MAX_DUTY 0.60` ก่อน
4. Upload แล้วเปิด Serial Monitor 115200 จด IP ที่ขึ้นมา

สถานะ: `IDLE → (g) RUNNING → 5 นาที → DONE`; ปุ่มหรือ `x` → `ESTOP` (ค้างจนกด `r` และปล่อยปุ่มแล้ว)

- ล้อหมุนได้เฉพาะ `RUNNING` และต้องได้คำสั่ง drive ทุก ≤300 ms ไม่งั้นหยุดเอง
- servo ขยับได้ใน `IDLE` (ไว้ calibrate) และ `RUNNING`; ใน `DONE/ESTOP` ค้างตำแหน่ง (ไม่ปล่อยหิน)
- ESP32 ส่งสถานะกลับไปที่ PC ทุก 200 ms (teleop แสดงบนจอ)
- **ตอนเปิดเครื่อง servo จะกระโดดไปที่ `SERVO_START_DEG`** ตั้งค่านี้ให้เป็นท่าที่ปลอดภัย
- อย่าต่ออุปกรณ์อื่นที่ pin servo (18, 19 ตามค่าเริ่มต้น) เพราะ firmware ส่งสัญญาณ servo ออกตลอด

### เครือข่าย

- PC กับ ESP32 ต้องอยู่ Wi-Fi เดียวกัน **ใช้ hotspot/router ของทีมเอง** เพราะ Wi-Fi มหาวิทยาลัยหรือสถานที่มักบล็อกอุปกรณ์คุยกันเอง (client isolation)
- ตั้ง IP ของ ESP32 ให้คงที่ (จองใน hotspot หรือกำหนดใน firmware)
- Firewall บน PC ปกติไม่ต้องแก้: ESP32 ตอบกลับมาที่พอร์ตที่ PC ส่งออกไป firewall ถือเป็นการตอบกลับจึงปล่อยผ่าน

## 2. ทดสอบโดยไม่มีหุ่น (fake_robot)

```bash
python fake_robot.py                                   # เทอร์มินัล 1
python teleop.py 127.0.0.1 --camera 0 --no-log         # เทอร์มินัล 2
```

`fake_robot.py` ทำงานเหมือน firmware ทุกอย่าง (state, หยุดเมื่อไม่มีคำสั่ง 300 ms, จับเวลา, servo, ส่งสถานะกลับ)
ทดสอบหมดเวลาเร็ว ๆ ได้ด้วย `python fake_robot.py --run-seconds 20`

## 3. ลำดับทดสอบกับหุ่นจริง (ยกล้อลอยก่อนเสมอ)

```bash
python teleop.py <ESP_IP> --no-log
```

1. ยังไม่กด `g` → กด `w` ต้อง**ไม่หมุน** (IDLE)
2. กด `g` → `w` ล้อทั้งสองต้องหมุนไปข้างหน้า ถ้าข้างไหนกลับ แก้ `L_INVERT/R_INVERT`
3. ปล่อยปุ่ม → หยุดภายใน ~0.6 s
4. กด `w` ค้าง แล้ว **ปิดโปรแกรม / ปิด Wi-Fi ของ PC** → ล้อต้องหยุดภายใน 0.3 s
5. กดปุ่ม e-stop ตอนล้อหมุน → หยุดทันที, จอขึ้น ESTOP; กด `r` ขณะยังกดปุ่มค้าง → ต้องไม่ reset
6. ทดสอบหมดเวลา: ตั้ง `RUN_TIME_MS` เป็น 20000 ชั่วคราว → ต้องเข้า DONE เอง (อย่าลืมคืนเป็น 300000)
7. servo: หาองศาด้วยคำสั่งดิบ แล้วเอาไปใส่ `GRIP_*`, `SERVO_MIN/MAX_DEG`
   ```python
   from teleop import Link; l = Link('<ESP_IP>', 4211); l.send('servo', i=0, deg=90)
   ```
8. ถ้า ESP32 รีเซ็ตตอน servo ขยับ (Serial ขึ้น boot ใหม่) = ไฟตก → แยกไฟ servo, ต่อ GND ร่วม, ลด `SERVO_DEG_PER_SEC`

### ปุ่มของ teleop.py

| ปุ่ม | หน้าที่ |
| --- | --- |
| `w` `s` | เดินหน้า / ถอยหลัง |
| `a` `d` | หมุนอยู่กับที่ |
| `q` `e` | เลี้ยวโค้งซ้าย / ขวา |
| `space` | หยุดล้อ |
| `+` `-` | ปรับความเร็ว |
| `g` | เริ่ม run (เริ่มนับ 5 นาที) |
| `x` | หยุดฉุกเฉิน (ค้างจนกด `r`) |
| `r` | reset หลังหยุดหรือหมดเวลา |
| `o` `c` `u` `j` | แขน: เปิด ปิด ยก วาง |
| `Esc` | ออก (ส่งคำสั่งหยุดให้อัตโนมัติ) |

โหมดปกติต้องกดค้างถึงจะวิ่ง ปล่อยแล้วหยุดภายใน 0.6 s ใส่ `--latch` ถ้าต้องการกดครั้งเดียวแล้ววิ่งต่อจนกด `space`
`teleop.py` เป็นเครื่องมือทดสอบ ไม่ใช่รีโมตแข่ง รอบ 1 ต้องใช้รีโมต gesture ซึ่งควรส่งคำสั่ง v3 แบบเดียวกัน

## 4. AprilTag

**สถานะ: เลื่อนไว้จนกว่าหลังคาจริงจะเสร็จ** ค่าที่ตัดสินใจแล้ว:

- ตระกูล **36h11**, ID 0 พิมพ์จาก `apriltag_36h11_id0.pdf` หน้า 1 (**tag 120 mm**) ถ้ามีอะไรบังให้ใช้หน้า 2 (100 mm)
- หลังคาเป็นฟิวเจอร์บอร์ด**สีดำ** 150 × 150 mm จึงต้องมีกระดาษขาวปิดเต็มหลังคา: ตัดตาม**เส้นประ 150 mm** ใน PDF
- พิมพ์แบบ **100% / Actual size** แล้ววัดสเกล 100 mm ให้ตรง ใช้กระดาษด้าน
- **ขอบบนของ tag (ลูกศร FRONT) = ด้านหน้าหุ่น** ใช้ PDF นี้ → `heading_offset_deg: 0`
  (ถ้าใช้ PNG ทางการจาก `AprilRobotics/apriltag-imgs` ลายเดียวกันแต่กลับหัว → ตั้ง `180`)

ค่าใน `calib.json` → `robot_tag`:

| ค่า | ความหมาย | สถานะ |
| --- | --- | --- |
| `id`, `family` | 0, `36h11` | ใช้ได้เลย |
| `size_mm` | ด้านของสี่เหลี่ยม**ดำ** (ไม่ใช่กระดาษ 150) | ใส่ 120 หลังวัดจริง |
| `height_mm` | พื้น → ผิว tag | วัดเมื่อหลังคาเสร็จ |
| `camera_height_mm` | พื้น → เลนส์ | วัดแล้ว (อยู่ใน config ในเครื่อง) |
| `camera_floor_xy_mm` | จุดบนพื้นใต้เลนส์ วัดจากมุมแรกที่คลิก (TL) | `[285, 975]` วัดแล้ว |
| `grip_offset_mm` | กลาง tag → ปากแขน [ไปข้างหน้า, ไปทางขวา] | รอแขน |
| `footprint_mm` | กลาง tag → ขอบหุ่นแต่ละด้าน | รอหุ่นจริง |
| `heading_offset_deg` | แก้ทิศของ tag | 0 |

ผลของค่าที่ผิด: ความคลาด ≈ ระยะจากใต้กล้อง × Δh / H ค่าที่ผิดจึงเห็นชัดที่**มุมสนาม**
กล้องอยู่ค่อนไปทางมุมล่างซ้าย มุม**ขวาบน**จึงไกลกล้องที่สุด ให้ทดสอบที่มุมนี้เป็นพิเศษ

ทดสอบ: `python robot_pose.py <กล้อง>` พิมพ์อัตราการเจอ tag และขนาด tag เป็นพิกเซล
เกณฑ์: เจอ ≥ 95% ทุกมุมตอนหุ่นวิ่ง, ตำแหน่ง 5 จุดที่วัดด้วยตลับเมตรคลาดไม่เกิน ~1 cm,
หันไป +x ได้ ~0°, หันลงล่างภาพได้ ~90° ถ้าขึ้น `size ... != ...` แปลว่า `height_mm`/`camera_height_mm` หรือการ calibrate มุมสนามผิด

## 5. เลือกหินและทิศเข้า

**เลือกก้อนไหน**
1. vision ให้หินเป็นเป้าหมายเมื่อสีมั่นใจ นิ่งหลายเฟรม และมีที่ให้แขน (ว่างรอบตัว หรือว่างอย่างน้อยหนึ่งทางที่กว้างเท่าแขน: `pile_mode`)
2. `TargetLock` เลือกก้อนที่ confidence สูงสุด (ต่อไปควรเป็นก้อนที่เส้นทาง หุ่น → หิน → โซนสี สั้นที่สุด)
3. ล็อกไว้จนวางเสร็จ (`done()`), หายเกิน 1 วินาที หรือเห็นเป็นสีอื่น สีที่ล็อกไม่เปลี่ยนตลอด ใส่ `occluded=True` ตอนหุ่นบังหินเองเพื่อไม่ให้หมดเวลา

**เข้าทางไหน** (`approach_deg` = ทิศที่หุ่นหันขณะขับเข้าหาหิน, 0 = +x, 90 = +y)
- ว่างรอบตัว → เข้าทางไหนก็ได้ (`approach_deg` ไม่มี)
- อยู่ในกอง → ทิศที่อยากได้คือออกจากกลางกอง; อยู่ใกล้สิ่งของ/ขอบ → ออกจากสิ่งที่ใกล้ที่สุด
- ลอง 16 ทิศ เริ่มจากทิศที่อยากได้ (ในกองไม่เกิน ±67.5°) ทิศแรกที่แถบกว้างเท่าแขนยาว 80 mm ว่าง ชนะ

**หุ่นทำอะไรต่อ** (`autonomy.py`): ขับไปจุดบนแถบนั้นห่างหิน ~160 mm → หมุนให้หันไปที่ `approach_deg` → ค่อย ๆ เดินเข้าจนปากแขน (`grip_x, grip_y`) ถึงหิน → `grip close` → ลากหินไปตามพื้นถึงโซนสีที่ล็อกไว้ → `grip open` → ถอย → `done()` (ไม่มีการยกแขน)

**กองหินตอนเริ่ม:** กองแน่น ๆ มีหินที่หยิบได้แค่ที่ขอบกอง ถ้าไม่เหลือก้อนที่หยิบได้ ให้ดันกองไป**ทางขวา** (ฝั่งโซนเริ่ม ไม่มีโซนสี) ห้ามดันไปทางโซนสี เพราะหินที่เข้าโซนผิดได้ −1

### V1 และ V2

มีสองเวอร์ชันที่ใช้ `calib.json` ตัวเดียวกันและ flag เหมือนกัน (ไม่มีการเขียนทับ `calib.json`):
`python autonomy.py ...` = **V1** พฤติกรรมเดิมที่ทดสอบในสนามแล้ว (หินที่ติดกันเป็นกองเห็นเป็น blob "?" ก้อนเดียว)
และ `python autonomy2.py ...` = **V2** = V1 + แก้กองหิน (`vision.pile_edge_pixels=nearest`), หินก้อนนอกสุดของกอง
(`vision.pile_outermost`), รายงานหินในกองเป็นสีของมัน (`vision.pile_regions`), ล็อกหินจนจบ (`commit_target`)
และลองหินก้อนเดียวที่ถูกข้ามอีกครั้งหลัง 6 s (`skip_alone_s`) ปิดทีละข้อได้ด้วย `--set` เช่น
`--set vision.pile_outermost=false` รายละเอียดอยู่ใน [profiles.py](profiles.py) และ README.md

## 6. บันทึก run (สำหรับวิเคราะห์ และ LeRobot ภายหลัง)

```bash
python teleop.py <ESP_IP> --camera 1
```

ได้ `runs/<เวลา>/`:
- `video.mp4` เฟรมกล้องดิบ → เล่นซ้ำด้วย `detect_live.py --video` หรือ `robot_pose.py --video` ได้
- `log.jsonl` 20 แถว/วินาที: `t`, `frame`, `action {l, r}`, `events` (start/stop/grip), `status` (state, servo, …), `pose`
- `meta.json` ค่าตั้งและ calib ที่ใช้ตอนนั้น

แต่ละแถวคือ (observation, action) ของ 1 timestep ตรงกับที่ LeRobotDataset ต้องการ ภายหลังเขียน converter ได้โดยไม่ต้องเก็บข้อมูลใหม่

## 7. สิ่งที่ยังค้าง

- รีโมต gesture (รอบ 1) ยังไม่ได้เริ่ม ฮาร์ดแวร์ยังไม่ได้ตัดสินใจ
- planner/autonomy loop ต้องรอแขนและ AprilTag บนหลังคาจริง
- firmware ยังไม่ได้ compile, pin และองศา servo เป็นค่าสมมติ
- ค่าเกี่ยวกับแขนใน `vision` (`gripper_width_mm`, `approach_length_mm`, `own_radius_mm`) เป็นค่าเดา
