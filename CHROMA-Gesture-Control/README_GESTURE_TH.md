# ควบคุมหุ่นด้วยสองมือผ่านกล้อง

ใช้กับ firmware `firmware/robot_ctrl` ปัจจุบันของ repo นี้ (UDP v3 พอร์ต 4211, IP คงที่ `10.178.188.50`)
**ค่าเริ่มต้นใช้โมเดลท่ามือสำเร็จรูปของ MediaPipe (Gesture Recognizer) ไม่ต้องเก็บข้อมูลหรือเทรน**
ถ้าต้องการ ยังเทรน MLP เองได้ ดู [คู่มือเก็บข้อมูลและฝึก MLP](TRAIN_GESTURES_TH.md)

## ติดตั้งและทดลองโดยไม่ต่อหุ่น

```powershell
.\setup_gesture.ps1
python gesture_control.py                                         # MediaPipe (ค่าเริ่มต้น)
python gesture_control.py --rules                                 # กฎเรขาคณิตเดิม
python gesture_control.py --classifier models/gesture_mlp.npz     # MLP ที่เทรนเอง (v1 มือเดียว)
```

บน Windows ใช้ `.\.venv-gesture\Scripts\python.exe` แทน `python` (หรือ activate venv ก่อน)
`setup_gesture.ps1` ดาวน์โหลด `models/gesture_recognizer.task` ให้
คะแนน MediaPipe ต่ำกว่า `--min-score` (ค่าเริ่มต้น 0.7) นับเป็น UNKNOWN

ค่าเริ่มต้นคือ PREVIEW ไม่เปิด socket และไม่ส่งคำสั่ง ใช้กล้องที่หันหาคนควบคุม ไม่ใช่กล้องเหนือสนาม
ภาพเป็นภาพสะท้อนเหมือนกระจก ถ้ากล้องผิดตัวเปลี่ยนเป็น `--camera 1`

## แบ่งหน้าที่สองมือ

จอแบ่งครึ่งด้วยเส้นแนวตั้ง **มือที่อยู่ครึ่งขวาของจอ = มือขับ, ครึ่งซ้าย = มือสั่งงาน**
(ตัดสินจากตำแหน่งบนจอ ไม่ใช่จากที่ MediaPipe เดาว่าเป็นมือซ้าย/ขวา)
คนถนัดซ้ายใส่ `--swap-hands` เพื่อสลับ

### มือขับ (ขวา)

| ท่า | ผล |
| --- | --- |
| แบมือในกรอบฟ้า ค้าง 0.5 วินาที | พร้อมขับ (READY) |
| แบมือเลื่อนขึ้น / ลงจากกรอบ | เดินหน้า / ถอยหลัง ตามหัวหุ่น |
| แบมือเลื่อนซ้าย / ขวาจากกรอบ | หมุนอยู่กับที่ซ้าย / ขวา (ความเร็ว 60% ของเกียร์) |
| แบมืออยู่ในกรอบ | หยุดล้อ |
| กำมือ ท่าอื่น มือหาย หรือมือข้ามเส้นกลาง | หยุดล้อ ต้องแบมือในกรอบใหม่ |

### มือสั่งงาน (ซ้าย)

| ท่า | ค้าง | ผล |
| --- | --- | --- |
| OPEN แบมือ | 0.3 วินาที | ท่าพัก: ต้องแบก่อนสั่งทุกครั้ง (ยกเว้น FIST) |
| ONE ชี้นิ้วชี้ขึ้น ☝ | 0.4 วินาที | เปิดปากคีบ (`grip open`, 0°) |
| ILOVEYOU 🤟 โป้ง+ชี้+ก้อย | 0.4 วินาที | ปิดปากคีบ (`grip close`, 40°) |
| THUMB_UP โป้งขึ้น | 0.4 วินาที | เพิ่มเกียร์ |
| THUMB_DOWN โป้งลง | 0.4 วินาที | ลดเกียร์ |
| V ชี้+กลาง | 0.8 วินาที | START: ขอให้หุ่นเข้า RUNNING |
| FIST กำมือ | 0.5 วินาที | STOP: หุ่นเข้า IDLE ทันที ไม่ต้องแบมือก่อน |

- MediaPipe ไม่มีท่าสามนิ้ว จึงใช้ 🤟 ปิดคีบแทน (ถ้าใช้ `--rules` / `--classifier` ท่า THREE ยังปิดคีบได้)
- ชื่อท่าของ MediaPipe: Open_Palm=OPEN, Closed_Fist=FIST, Victory=V, Pointing_Up=ONE,
  Thumb_Up / Thumb_Down, ILoveYou; `None` หรือคะแนนต่ำ = UNKNOWN
- สองมือทำงานพร้อมกันได้ เช่น ขับไปพร้อมปิดคีบ หรือเปลี่ยนเกียร์ระหว่างวิ่ง
- ระหว่าง PAUSED มือสั่งงานใช้ได้แค่ V (start) และ FIST (stop)
- มือสองข้างอยู่ครึ่งเดียวกัน → หยุดทุกอย่าง
- ท่าแต่ละท่าสั่งครั้งเดียวต่อการค้าง ค้างต่อไม่สั่งซ้ำ

### เกียร์

| เกียร์ | คำสั่งล้อ | duty ที่ firmware ใช้ประมาณ |
| --- | --- | --- |
| 1 (เริ่มต้น) | 0.15 | 0.75 |
| 2 | 0.35 | 0.81 |
| 3 | 0.60 | 0.88 |

firmware แปลงคำสั่ง 0<|cmd|≤1 เป็น duty 0.71–1.0 แบบเส้นตรง (`MIN_DUTY 0.71` คือ duty ที่ล้อเริ่มหมุนพอดี)
จึงเป็นความเร็วที่ต่างกันจริง เกียร์ 1 ใกล้กับ `creep 0.18` ที่ autonomy ใช้เข้าหาหิน
ปรับได้ด้วย `--gears 0.12,0.3,0.6,1.0` (เรียงน้อยไปมาก, ≤1) HUD แสดงเกียร์และ duty โดยประมาณ

## ปุ่มคีย์บอร์ด (คลิกหน้าต่างก่อน)

| ปุ่ม | หน้าที่ |
| --- | --- |
| G | START เหมือน V: ส่ง `start` แล้วรอสถานะ RUNNING ภายใน 1 วินาที |
| Space | พัก: หยุดล้อฝั่ง PC หุ่นยังอยู่ RUNNING กลับด้วย G |
| X | STOP เหมือน FIST: ส่ง `stop` หุ่นเข้า IDLE (ไม่ค้างสถานะ กด G เริ่มใหม่ได้เลย) |
| Esc / ปิดหน้าต่าง | ออก: ส่งล้อศูนย์และ `stop` |

firmware ปัจจุบันมีแค่ IDLE / RUNNING ไม่มี ESTOP ค้าง ไม่มีคำสั่ง reset และไม่มีตัวจับเวลา 5 นาที

## การหยุดและข้อจำกัด (ตามของที่มีจริง)

สิ่งที่หยุดล้อได้:

- **firmware**: ไม่ได้รับ `drive` เกิน 300 ms หรือ Wi-Fi หลุด → ล้อหยุด; `stop` → IDLE
- **PC**: มือขับอายุเกิน 200 ms / หาย / ข้ามเส้นกลาง / ไม่ใช่ OPEN → ส่งล้อศูนย์
- **PC**: สถานะหุ่นหายเกิน 600 ms หรือไม่ใช่ RUNNING → พัก ต้องกด G / V ใหม่

สิ่งที่ **ไม่มี**:

- **ไม่มีปุ่มหยุดฉุกเฉินบนหุ่น** firmware ปัจจุบันไม่มี `ESTOP_PIN` ต้องมีคนพร้อมยกหุ่นหรือปิดสวิตช์ไฟ
- ไม่มีตัวจับเวลาหมดรอบบนหุ่น
- `stop` ไม่ค้างสถานะ: ใครก็ตามส่ง `start` ได้อีก

อื่น ๆ:

- หยุดล้อไม่ยกเลิกการขยับ servo ที่สั่งไปแล้ว คำสั่งคีบส่งครั้งเดียวทาง UDP อาจหายได้ ดูมุม servo บน HUD
- อายุภาพวัดก่อน camera read จึงรวมเวลาอ่าน/ประมวลผล แต่ไม่รู้ว่า driver กล้องค้างภาพเก่าไว้หรือไม่
- ต้องวัด latency และระยะหยุดจริงเอง ค่าข้างบนไม่ใช่หลักฐานว่าปลอดภัยบนฮาร์ดแวร์

```powershell
.\.venv-gesture\Scripts\python.exe -m unittest discover -s tests -p "test_gesture*.py" -v
```

ผ่าน 37 tests (29 กันยายน 2026); MediaPipe Gesture Recognizer อ่านภาพตัวอย่างของ Google
ผ่าน pipeline จริงได้ถูก 4/4 (Victory 0.86, Thumb_Up 0.76, Thumb_Down 0.93, Pointing_Up 0.92) และทดสอบวงรอบ `gesture_control.py --live` กับ `fake_robot.py`
ด้วยท่ามือจำลอง: V → RUNNING, ขับเกียร์ 1 → 2, ปิดคีบระหว่างขับ, FIST → IDLE
ยังไม่ได้ทดสอบกับเว็บแคมจริงหรือหุ่นจริง
