# ควบคุม CHROMA ด้วยท่ามือผ่านกล้อง

**เทรนท่ามือของเราเองได้แล้ว:** ดู [คู่มือเก็บข้อมูลและฝึก MLP](TRAIN_GESTURES_TH.md)
คำสั่งเดิมที่ไม่มี `--classifier` ยังใช้กฎ ส่วนโมเดลที่ฝึกเองเปิดด้วย:

```powershell
.\.venv-gesture\Scripts\python.exe gesture_control.py --camera 0 --classifier models/gesture_mlp.npz
```

ส่วนเพิ่มสำหรับโปรโตคอล UDP v3 ใน `firmware/robot_ctrl` ของ
`CPE-Exploratory3-main.zip` ไม่ใช่ receiver v2 ใน workspace เดิม
ไม่ได้แก้หรือแทนที่ firmware จาก ZIP และยังไม่ได้ทดสอบกับหุ่นจริง

## ติดตั้งและทดลองโดยไม่ต่อหุ่น

เปิด PowerShell ในโฟลเดอร์นี้ ใช้ Python 3.12:

```powershell
.\setup_gesture.ps1
.\.venv-gesture\Scripts\python.exe gesture_control.py --camera 0
```

สคริปต์ติดตั้งสร้าง `.venv-gesture` แยกจากโปรแกรมสนาม และดาวน์โหลดโมเดลจาก
Google มาที่ `models/hand_landmarker.task` หลังติดตั้งอ่านมือในเครื่องได้
หากกล้องผิดตัว เปลี่ยน `--camera 0` เป็น `--camera 1`
ใช้กล้องโน้ตบุ๊กหันหาคนควบคุม แยกจากกล้องเหนือสนาม
ค่าเริ่มต้นคือ PREVIEW ไม่เปิด socket และไม่ส่งคำสั่ง แม้ระบุ `--robot` ก็ตาม

## ท่าควบคุม

กด G เพื่อเริ่มทดลอง จากนั้นแบมือกลางกรอบค้าง 0.5 วินาทีเพื่อพร้อมควบคุม
ใช้มือเดียว หันฝ่ามือเข้ากล้อง ภาพสะท้อนเหมือนกระจก

| โหมด | ท่า | คำสั่ง |
| --- | --- | --- |
| DRIVE | แบมือกลางกรอบ | หยุดล้อ |
| DRIVE | แบมือเลื่อนขึ้น / ลงจากกรอบ | เดินหน้า / ถอยหลัง ตามทิศหัวหุ่น |
| DRIVE | แบมือเลื่อนซ้าย / ขวา | หมุนซ้าย / ขวา ตามทิศหัวหุ่น |
| DRIVE | กำมือ หรือท่าที่ไม่ใช่แบมือ | หยุด และต้องแบมือกลางกรอบใหม่ |
| ทั้งสองโหมด | ชู V (นิ้วชี้+กลาง) ค้าง 0.8 วินาที | สลับ DRIVE / ARM และหยุดล้อ |
| ARM | ชูนิ้วชี้นิ้วเดียว ค้าง 0.4 วินาที | เปิดคีบ |
| ARM | ชูนิ้วชี้+กลาง+นาง ค้าง 0.4 วินาที | ปิดคีบ |
| ARM | กำสี่นิ้ว ชูนิ้วโป้งขึ้น ค้าง 0.4 วินาที | ยกแขน |
| ARM | กำสี่นิ้ว ชี้นิ้วโป้งลง ค้าง 0.4 วินาที | ลดแขน |

หลังเปลี่ยนโหมด และหลังคำสั่งแขนแต่ละครั้ง ต้องแบมือกลางกรอบ 0.5 วินาทีก่อน
สั่งครั้งต่อไป โหมด ARM ไม่ขับล้อ การกำมือ/มือหายหยุดล้อ แต่ไม่ย้อนหรือยกเลิก
คำสั่งเซอร์โวที่ส่งไปแล้ว ถ้าต้องหยุดทั้งล้อและการขยับเซอร์โวใช้ X
ตรวจข้อความ Pose ให้ถูกก่อนต่อหุ่น: การจำแนกท่าเป็นกฎจากจุดมือ ไม่รับประกันทุกมุม

| ปุ่ม | หน้าที่ |
| --- | --- |
| G | เริ่ม/กลับมาควบคุม; LIVE ขอ start และรอสถานะ RUNNING |
| Space | พักและหยุดล้อ; กลับด้วย G |
| X | ESTOP; LIVE ส่ง stop แบบค้างสถานะ |
| R | ขอ reset หลัง ESTOP/หมดเวลา แล้วค่อยกด G |
| Esc / ปิดหน้าต่าง | ออก; LIVE ส่งล้อศูนย์และ stop |

ต้องคลิกหน้าต่างก่อนใช้ปุ่ม คีย์บอร์ดใช้เริ่ม/หยุด ส่วนขับและแขนใช้ท่ามือ
เอกสารโครงการยังไม่ระบุว่าการใช้ปุ่มเริ่ม/หยุดร่วมกับ gesture ได้หรือไม่
ควรยืนยันกับผู้สอนก่อนแข่งขัน

## ต่อหุ่นหลังผ่าน preview

ต้องใช้ firmware `robot_ctrl` v3 จาก ZIP ตั้งขาและมุมเซอร์โวให้ตรงกับของจริง
compile/flash และทดสอบระบบหยุดตาม README_ROBOT ของชุดนั้นก่อน
หยุดโปรแกรม teleop อื่น เพื่อให้มีผู้ส่งคำสั่งเพียงตัวเดียว

```powershell
.\.venv-gesture\Scripts\python.exe gesture_control.py --camera 0 --robot 192.168.1.50 --live --speed 0.25
```

เปลี่ยน IP ให้ตรงกับหุ่น ใช้ UDP port 4211 ค่า speed เป็นสัดส่วนคำสั่งมอเตอร์
ไม่ใช่เมตรต่อวินาทีและไม่ใช่การควบคุมความเร็วแบบมี feedback
เริ่มจากล้อยกพ้นพื้นและแขนมีที่ว่าง G เริ่มจับเวลา 5 นาทีตาม firmware
สถานะ servo ที่ firmware ส่งกลับเป็นค่าที่สั่ง ไม่ใช่มุมที่วัดจากเซนเซอร์
คำสั่งแขนส่งครั้งเดียวผ่าน UDP อาจสูญหายได้ ให้ดูแขนจริงแล้วกลับท่ากลางก่อนสั่งซ้ำ

## การหยุดและขอบเขตการทดสอบ

- ข้อมูลมืออายุเกิน 200 ms / ไม่พบมือ / พบหลายมือ -> ล้อศูนย์และต้องกลับท่ากลาง
- กล้องและ inference อยู่คนละ thread กับตัวส่ง หาก camera read ค้าง ตัวส่งตรวจอายุได้
- สถานะหุ่นหายเกิน 600 ms หรือไม่ใช่ RUNNING -> พัก ต้องกด G ใหม่
- ส่ง drive ประมาณ 20 Hz; firmware มี watchdog ล้อ 300 ms หากตัวโปรแกรมหยุดทำงาน
- X เป็นการหยุดผ่านซอฟต์แวร์และเครือข่าย ต้องคงปุ่มหยุดบนหุ่นไว้ด้วย
- อายุภาพวัดก่อนเรียก camera read จึงรวมเวลาอ่านและประมวลผล แต่ไม่ทราบอายุภาพ
  ที่ค้างใน driver กล้อง และไม่ตรวจจับอุปกรณ์ที่ส่งภาพเก่าซ้ำด้วย timestamp ใหม่
- ต้องวัด latency และระยะหยุดจริง ไม่ให้ค่าข้างต้นเป็นหลักฐานว่าปลอดภัยบนฮาร์ดแวร์

```powershell
python -m unittest discover -s tests -p test_gesture.py -v
```

ชุดทดสอบตรวจตรรกะ timeout, การกลับท่ากลาง, การสลับโหมด, คำสั่งแขนครั้งเดียว
และแพ็กเก็ตผ่าน UDP loopback ไม่ยืนยันความแม่นยำอ่านมือหรือการทำงานของมอเตอร์
ใน ZIP ไม่มี fake_robot.py แม้เอกสารอ้างถึง จึงไม่ได้อ้างว่าใช้ simulator นั้นทดสอบ
