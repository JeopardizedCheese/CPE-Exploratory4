# CHROMA Virtual Lever — รุ่นแรก (ระบบควบคุมด้วยมือหลัก)

ควบคุมหุ่นด้วยมือเดียว: กำมือโยกเพื่อขับ ยกนิ้วโป้งเพื่อเข้าโหมด servo แล้วโยกทั้งมือขึ้น/ลงเพื่อหนีบ/ปล่อย

รุ่นนี้ใช้ตำแหน่งบนภาพ 2 มิติ ไม่ได้วัดการดันมือเข้า/ออกจากกล้อง และยังไม่ใช่ร่องเกียร์ตัว H
ใช้ MediaPipe สำเร็จรูปบนเครื่องที่ต่อกล้อง ไม่ต้องเทรน ไม่ต้องใช้ A100

## เปิดใช้งาน

เปิด PowerShell ใน `CHROMA-Gesture-Control` ใช้ Python 3.12 แล้วติดตั้งครั้งแรก:

```powershell
.\setup_lever.ps1
```

ถ้าคำสั่ง `python` ไม่พบ ให้ระบุ Python ที่ติดตั้งจริง:

```powershell
.\setup_lever.ps1 -Python 'C:\path\to\python.exe'
```

การติดตั้งดาวน์โหลด dependencies จากอินเทอร์เน็ต โมเดล Gesture Recognizer มีอยู่แล้วใน `models/`

**ทดลองโดยไม่ใช้กล้องหรือหุ่น:**

```powershell
.\.venv-gesture\Scripts\python.exe lever_control.py --demo
```

- กด `G` เพื่อเริ่ม จากนั้นวางเมาส์ในกรอบกลางของภาพซ้าย
- เมาส์ในภาพซ้ายแทนตำแหน่งมือ; `1` กำมือ, `2` ยกนิ้วโป้ง, `3` แบมือ
- `0` จำลองมือหาย; `4` จำลองพบสองมือ
- Demo ไม่สามารถใช้ร่วมกับ `--live` ได้

**ทดลองกับกล้อง โดยยังไม่เชื่อมต่อหุ่น:**

```powershell
.\.venv-gesture\Scripts\python.exe lever_control.py --camera 0
```

ถ้ากล้องผิดตัว เปลี่ยนเป็น `--camera 1` ปิดแอปอื่นที่ใช้งานกล้องอยู่ก่อน
หากเปิดหน้าต่างได้แต่ขึ้นข้อความ Cannot open camera ให้ตรวจหมายเลขกล้องและสิทธิ์กล้องของ Windows

**เชื่อมต่อหุ่นจริง:** ใช้ firmware [`../firmware/robot_ctrl`](../firmware/robot_ctrl) และอยู่ในเครือข่ายเดียวกับหุ่น

```powershell
.\.venv-gesture\Scripts\python.exe lever_control.py --camera 0 --live --robot 10.178.188.50 --min-duty .65
```

`--min-duty .65` ส่ง floor 0.65 ไปกับทุก drive packet (แบบเดียวกับ `autonomy.py --set min_duty=0.65`)
ถ้าไม่ใส่ หุ่นใช้ `MIN_DUTY` 0.71 ของ firmware ถ้า firmware ไม่รายงาน `min_duty` โปรแกรมจะหยุดเอง
เปลี่ยน IP ให้ตรงกับหุ่นจริง โปรแกรมต้องได้รับสถานะ RUNNING ที่ระบุ session ของตัวเองก่อนยอมให้ขับ
ปิดโปรแกรมควบคุมหุ่นตัวอื่นก่อน รุ่นนี้ไม่ได้แก้หรือแฟลช firmware และไม่รวมรหัส Wi-Fi

## วิธีบังคับ

| สิ่งที่ทำ | ผลลัพธ์ |
|---|---|
| กด G | เปิดรับการควบคุม; live ส่ง START และรอสถานะหุ่น |
| กำมือค้างนิ่งในกรอบกลาง 0.5 วินาที | บันทึกจุดกลางและเข้า DRIVE |
| กำมือแล้วเลื่อนขึ้น / ลงบนภาพ | เดินหน้า / ถอยหลัง |
| กำมือแล้วเลื่อนซ้าย / ขวาบนภาพ | หมุนซ้าย / ขวา |
| มือกลับกรอบกลาง | คำสั่งล้อเป็นศูนย์ |
| ยกนิ้วโป้ง | สั่งล้อเป็นศูนย์ทันที แล้วรอท่าค้างนิ่ง 0.5 วินาที |
| คงนิ้วโป้งในกรอบกลางใหม่อีก 0.3 วินาที | พร้อมสั่ง servo; แค่เปลี่ยนโหมดจะยังไม่หนีบ |
| ยกนิ้วโป้งไว้ แล้วโยกทั้งมือขึ้นผ่านเส้น CLOSE ค้าง 0.15 วินาที | หนีบ |
| กลับกรอบกลางค้าง 0.3 วินาที แล้วโยกลงผ่านเส้น OPEN | ปล่อย |
| แบมือ / ท่าไม่ชัด / มือหาย / พบมากกว่าหนึ่งมือ | ยกเลิกโหมดและสั่งล้อเป็นศูนย์ โดยคงก้ามไว้ |
| SPACE หรือ X | หยุดและพัก; live ส่ง STOP ให้หุ่นเข้า IDLE |
| `+` / `-` | เพิ่ม/ลดระดับคำสั่งทีละ 0.05 (0.02–1.00) มีผลทันทีแม้กำลังขับ ไม่ต้อง arm ใหม่ |
| ESC หรือปิดหน้าต่าง | ส่งคำสั่งหยุดและปิดโปรแกรม |

หลังยกเลิกโหมดด้วยท่ามือ ต้องกำมือกลับกรอบกลางเพื่อเริ่มใหม่
หลัง SPACE/X หรือสถานะหุ่นขาด ต้องกด G ใหม่ด้วย
การพับนิ้วโป้งในโหมด servo จะยกเลิกโหมด ไม่เปลี่ยนกลับเป็นขับในทันที

ใช้มือซ้ายหรือขวาก็ได้ แต่ให้เห็นเพียงมือเดียว ภาพกล้องเป็นภาพกระจก
ตอนตั้งจุดกลาง servo ให้มืออยู่ห่างขอบภาพ เพื่อเหลือระยะโยกขึ้นและลงได้ทั้งสองทิศ
วางกล้องเฉียงให้การโยกหน้า–หลังปรากฏเป็นขึ้น–ลงบนจอ และตรวจทิศทางใน preview ก่อน
รุ่นแรกเป็นความแรงคงที่เมื่อออกจากกรอบกลาง ไม่ได้เร่งตามระยะมือ และไม่ใช่การเลือกเกียร์ค้าง

## ค่าที่ควรรู้ก่อนทดสอบกับกลไก

- `--speed .15` คือค่าคำสั่งเริ่มต้น ไม่ใช่ความเร็ว 15%: PWM = floor + คำสั่ง × (1 − floor) ที่ floor 0.71 (firmware) ได้ประมาณ 75.4%, ที่ `--min-duty .65` ได้ประมาณ 70.3% หน้าจอแสดง PWM และ floor ที่ใช้ (รับค่าคำสั่ง 0.02–1.00)
- เพราะ floor การกด `-` ลดความเร็วได้ไม่มากที่ระดับต่ำ (0.15 → 0.02 เปลี่ยน PWM แค่ ~4%) ถ้าต้องช้ากว่านั้นให้ลด `--min-duty` แต่ต่ำเกินไปล้ออาจไม่หมุน (เคยวัดได้ว่าหมุนตัวเริ่มหมุนที่ ~0.60–0.65)
- การหยุดคือการส่งคำสั่งศูนย์/STOP; ระยะและเวลาหยุดจริงขึ้นกับ firmware มอเตอร์ และกลไก ต้องทดลองกับล้อยกพ้นพื้นก่อน
- ก้ามใช้คำสั่ง `grip open/close` มุมจริงกำหนดใน firmware `config.h` (`GRIP_OPEN_DEG` 0 / `GRIP_CLOSE_DEG` 100 ณ 1 ต.ค. 2026) ตรวจให้ตรงกับกลไกจริง
- ค่า servo บนหน้าจอเป็นมุมที่ firmware คำนวณ ไม่ใช่เซนเซอร์ยืนยันว่าวัตถุถูกหนีบสำเร็จ
- ภาพเก่ากว่า 0.2 วินาทีทำให้ยกเลิกการควบคุม; สถานะหุ่นเก่าตั้งแต่ 0.6 วินาทีทำให้หยุดและต้องกด G ใหม่
- ส่งล้อทุกประมาณ 50 ms และส่งศูนย์ทันทีเมื่อเปลี่ยนจากขับเป็นหยุด; มี watchdog เดิมใน firmware อีกชั้น
- หนีบ/ปล่อยส่งเป้าหมายเดิมซ้ำรวม 3 ครั้งเพื่อทนต่อ UDP ตกหล่นเล็กน้อย ไม่ใช่การรับประกันส่งสำเร็จหรือยืนยันการหนีบ
- “Frame age” รวมเวลาอ่านภาพและประมวลผลฝั่งเครื่อง ไม่ใช่ค่าความหน่วงจากมือถึงมอเตอร์ทั้งหมด

## ตรวจสอบก่อนนำไปใช้

1. ใน Demo: ขับสี่ทิศทาง กลับกลาง แล้วเปลี่ยนเป็นนิ้วโป้ง; ล้อต้องเป็นศูนย์ตลอดโหมด servo
2. สั่ง CLOSE ค้างไว้ ต้องออก event เพียงครั้งเดียว; สั่ง OPEN ได้หลังกลับกลาง
3. ใช้กล้องจริงทดสอบกำมือ/นิ้วโป้ง/แบมือ ในแสงและระยะที่จะใช้งาน รวมถึงเอามือออกจากภาพ
4. ทดสอบหุ่นโดยยกล้อพ้นพื้นก่อน ตรวจซ้าย–ขวา ทิศมอเตอร์ มุมก้าม และการหยุดเมื่อกล้อง/เครือข่ายขาด
5. จึงทดสอบบนพื้นด้วยพื้นที่ว่าง พร้อมปุ่มหยุดที่หุ่นเข้าถึงได้

ผลทดสอบซอฟต์แวร์อยู่ใน `VALIDATION.md`; ยังไม่ได้ตรวจความแม่นของท่ามือหรือความหน่วงกับกล้องและหุ่นจริง

## ไฟล์หลัก

- `lever_control.py` — โปรแกรมกล้อง / Demo และหน้าจอ
- `lever_logic.py` — การแบ่งโหมด จุดกลาง และท่าบังคับ
- `lever_link.py` — ตรวจสถานะหุ่นและส่ง UDP v3 พอร์ต 4211
- `gesture_control.py`, `gesture_logic.py`, `gesture_model.py` — ส่วนอ่านกล้อง/โปรโตคอลที่นำมาจาก ZIP ต้นทาง โดยคงไฟล์เดิมไว้
- `models/` — โมเดล MediaPipe จาก ZIP ต้นทาง
- `tests/` — ทดสอบรุ่นใหม่และส่วนพื้นฐานที่นำกลับมาใช้

เปิดรุ่นนี้ด้วย **lever_control.py** ซึ่งเป็นระบบหลักตั้งแต่ 1 ต.ค. 2026; `gesture_control.py` เป็นระบบสองมือเดิม (เลิกใช้ เก็บไว้สำรอง)

```powershell
.\.venv-gesture\Scripts\python.exe -m unittest discover -s tests -v
```

ค่าจุดกลางและเวลาเริ่มต้นปรับได้ใน `LeverControl` ใน `lever_logic.py`
