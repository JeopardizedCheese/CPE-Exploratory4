# เทรนท่ามือของเราเอง

ลำดับใช้งาน:

**กล้อง → MediaPipe หาจุดมือ → MLP ที่เราเทรน → ตรวจคะแนน/ความกำกวม →
ตัวควบคุมโหมดและระบบหยุด → UDP v3 → ESP32**

เราเทรนเฉพาะตัวจำแนกท่า ใช้ตัวตรวจมือของ MediaPipe ที่ฝึกแล้วต่อไป
โมเดลเป็น MLP ขนาด 64 และ 32 หน่วยในชั้นซ่อน ฝึกบน CPU
เป็นท่าค้าง ไม่ใช่โมเดลเรียนรู้ลำดับโบกมือหรือการปัด
MLP แทนกฎจำแนกรูปนิ้ว ส่วนตำแหน่งมือที่ใช้ขับ โหมดขับ/แขน และระบบหยุดยังทำงานเดิม

## 1. เปิดตัวเก็บข้อมูล

ใน PowerShell ที่โฟลเดอร์ CHROMA-Gesture-Control:

```powershell
.\setup_gesture.ps1
.\.venv-gesture\Scripts\python.exe gesture_collect.py --camera 0
```

เมื่อนำ ZIP ไปใช้บนเครื่องใหม่ ให้รัน setup_gesture.ps1 ก่อนใช้งานครั้งแรก
เลือกกล้องที่มองเห็นผู้ควบคุม ไม่ใช่กล้องเหนือสนาม
คลิกหน้าต่างก่อนกดปุ่ม โปรแกรมนี้ไม่เชื่อมต่อหุ่น

| ปุ่ม | คลาส | ตัวอย่างท่า |
| --- | --- | --- |
| 1 | OPEN | แบมือ ใช้พร้อมควบคุมและขับ |
| 2 | FIST | กำมือ หยุดล้อ |
| 3 | V | นิ้วชี้และกลาง สลับโหมด |
| 4 | ONE | นิ้วชี้นิ้วเดียว เปิดคีบ |
| 5 | THREE | นิ้วชี้ กลาง นาง ปิดคีบ |
| 6 | THUMB_UP | กำสี่นิ้ว โป้งขึ้น ยกแขน |
| 7 | THUMB_DOWN | กำสี่นิ้ว โป้งลง ลดแขน |
| 8 | UNKNOWN | ท่าอื่นที่ไม่ใช่เจ็ดท่าข้างบน เช่น งอนิ้วครึ่งหนึ่ง/อยู่ระหว่างเปลี่ยนท่า |

เลือกเลข → กด **R** → มีเวลาเตรียมท่า 2 วินาที → บันทึกอัตโนมัติ 60 ตัวอย่าง
อัตราสูงสุด 5 ตัวอย่างต่อวินาที ใช้เวลาบันทึกอย่างน้อยประมาณ 12 วินาทีต่อครั้ง
เมื่อมือหาย ภาพช้า หรือพบหลายมือ จะไม่เพิ่มตัวอย่าง
ป้ายชื่อมาจากเลขที่คุณเลือก ไม่ได้เอาคำทำนายของกฎเดิมมาเป็นคำตอบฝึก

- ระหว่างบันทึกให้เปลี่ยนระยะและมุมเล็กน้อยโดยยังเป็นท่าเดิม
- S = บันทึกที่เก็บได้แล้วและหยุด; R = บันทึกเพิ่ม
- D = ทิ้งรอบที่กำลังเก็บโดยไม่บันทึก
- U = ยกเลิกไฟล์ล่าสุดที่บันทึกในการเปิดโปรแกรมครั้งนี้ (ย้ายไว้ใน `discarded/`)
- Esc = บันทึกส่วนที่เก็บได้และออก
- เก็บเฉพาะตัวเลขจุดมือ ไม่มีการบันทึกภาพใบหน้าหรือวิดีโอ และไม่อัปโหลดข้อมูล

UNKNOWN ต้องยังมีมือที่ MediaPipe ตรวจได้ อย่าเอามือออกนอกภาพเพื่อเก็บคลาสนี้
เมื่อไม่พบมือ โปรแกรมควบคุมจะหยุดผ่านอีกเงื่อนไขหนึ่งอยู่แล้ว
ท่าที่ถูกบังจนตรวจมือไม่ได้จะไม่เข้า dataset ต้องทดสอบกรณีนั้นใน preview แยกด้วย

## 2. เก็บให้ครบอย่างน้อย 5 รอบการถ่าย (sessions)

หนึ่ง session ควรมี **ครบ 8 คลาส คลาสละ 60–100 ตัวอย่าง** เป็นจุดเริ่มต้น
จำนวนนี้ไม่ได้รับประกันความแม่นยำ โดยตัวฝึกตรวจขั้นต่ำ 30 ตัวอย่าง/คลาส/session

เมื่อครบหนึ่ง session ให้ปิดโปรแกรม เปลี่ยนระยะ แสง ฉากหลัง หรือผู้ควบคุม
แล้วเปิดใหม่เพื่อเริ่มอีก session แยกกันจริง ๆ ทำจนครบอย่างน้อย 5 sessions
หากใช้งานทั้งมือซ้าย/ขวาหรือหลายคน ต้องเก็บให้ครอบคลุมด้วย
ไม่ควรค้างมือเหมือนเดิมแล้วเปิด–ปิดห้ารอบเพื่อเพิ่มจำนวน session อย่างเดียว

โปรแกรมพิมพ์ session ID ใน terminal หากหยุดกลางคันและจะเก็บต่อสภาพเดิม:

```powershell
.\.venv-gesture\Scripts\python.exe gesture_collect.py --camera 0 --session SESSION_ID
```

แทน SESSION_ID ด้วยค่าที่โปรแกรมพิมพ์ ข้อมูลอยู่ใต้ `gesture_data/SESSION_ID/`
ตรวจจำนวนตัวอย่างได้ด้วย:

```powershell
.\.venv-gesture\Scripts\python.exe gesture_train.py --inspect
```

ตัวฝึกแบ่ง session ทั้งกลุ่มเป็น train/validation/test หากมี 5 sessions จะใช้ 3/1/1
ภาพใกล้กันจาก session เดียวจะไม่ข้ามกลุ่ม ตัวฝึกแจ้งข้อผิดพลาดหาก session ใดขาดคลาส
หรือข้อมูลยังไม่พอ ให้ resume เก็บต่อก่อน ไม่สุ่มเฟรมจากคลิปเดียวมาชดเชย
การแบ่งนี้วัดกับรอบถ่ายใหม่ ไม่ได้รับประกันว่าใช้กับคนใหม่ที่ไม่เคยฝึกได้

## 3. เทรน

```powershell
.\.venv-gesture\Scripts\python.exe gesture_train.py
```

ได้สองไฟล์:

- `models/gesture_mlp.npz` — โมเดลของคุณ รวมการปรับสเกลและชื่อคลาส
- `models/gesture_mlp.report.json` — จำนวนข้อมูล กลุ่มที่ใช้ คำเตือน และผลประเมิน

โมเดลใช้ตำแหน่งจุดมือเทียบกับข้อมือและขนาดฝ่ามือ เพื่อไม่ผูกกับตำแหน่ง/ขนาดในภาพ
ยังเก็บทิศทางมือไว้เพื่อแยกโป้งขึ้น–ลง ค่าปรับสเกลเรียนรู้จาก train เท่านั้น
ตัวฝึกไม่ใช้ validation หรือ test ปรับน้ำหนัก และไม่ใช้การสุ่มเฟรมภายในเพื่อ early stopping

ตรวจรายงานส่วน validation ก่อน: ตารางสับสน, recall แต่ละท่า, คำสั่งผิด (`wrong_active_commands`)
และท่า UNKNOWN ที่หลุดเป็นคำสั่ง (`unknown_to_active_rate`)
มีผลจากกฎเดิม (`original_rules`) ให้เทียบกับโมเดลบนข้อมูลชุดเดียวกัน
OPEN และ V นับเป็น active ด้วย เพราะทำให้ขับหรือเปลี่ยนโหมดได้
ตัวเลขเหล่านี้เป็นระดับเฟรม ไม่ใช่อัตราสำเร็จของหุ่น

เริ่มต้นปฏิเสธเมื่อคะแนนสูงสุดต่ำกว่า 0.9 หรือห่างจากอันดับสองน้อยกว่า 0.2
คะแนนโมเดลไม่ได้ผ่านการ calibrate จึงไม่ควรอ่าน 0.9 ว่าแม่นจริง 90%
ปรับ threshold ด้วย validation เท่านั้น ตัวอย่างสร้างรุ่นใหม่:

```powershell
.\.venv-gesture\Scripts\python.exe gesture_train.py --threshold 0.95 --margin 0.25 --output models/gesture_v2.npz
```

โปรแกรมไม่เขียนทับโมเดลเดิม หากดู test แล้วนำผลไปปรับอีก ต้องเก็บชุดทดสอบใหม่ที่ไม่เคยใช้
หากมีคำเตือนเรื่องไม่ลู่เข้า ให้ตรวจข้อมูล/จำนวนรอบฝึกและผล validation ก่อนใช้จริง
คะแนนไม่มั่นใจจะกลายเป็น UNKNOWN; โมเดลยังอาจมั่นใจผิดกับท่าที่ไม่เคยเห็นได้

## 4. ทดลองโมเดลโดยยังไม่ต่อหุ่น

```powershell
.\.venv-gesture\Scripts\python.exe gesture_control.py --camera 0 --classifier models/gesture_mlp.npz
```

หน้าจอต้องขึ้น **PREVIEW | MLP** แล้วกด G และแบมือกลางกรอบ
แสดงทั้งคำทำนายก่อนปฏิเสธ คะแนน และท่าที่ส่งให้ตัวควบคุม
หากไม่ใส่ `--classifier` จะขึ้น RULES และใช้กฎเดิมอย่างชัดเจน
หากระบุโมเดลแล้วโหลดไม่ได้ โปรแกรมจะหยุดพร้อมข้อผิดพลาด ไม่แอบย้อนกลับไปใช้กฎ

ทดลองเปลี่ยนท่าเร็ว/ช้า พักมือ เอามือออกจากภาพ ให้คนอื่นเดินผ่าน และเปลี่ยนแสง
จับจำนวนคำสั่งผิดและดูว่าหุ่นจำลองบน HUD หยุดเมื่อควรหยุดหรือไม่
อย่าดูเฉพาะตอนค้างท่าสวย ๆ หน้ากล้อง

เมื่อผ่าน preview และทดสอบ firmware ตามคู่มือแล้วจึงเพิ่ม `--robot IP --live`
การควบคุมและปุ่มหยุดอ่านต่อได้ใน [README_GESTURE_TH.md](README_GESTURE_TH.md)

## การตรวจซอฟต์แวร์

```powershell
.\.venv-gesture\Scripts\python.exe -m unittest discover -s tests -p "test_gesture*.py" -v
```

มีการทดสอบ normalization, การไม่เก็บเฟรมซ้ำ/หมดอายุ, การใช้ป้ายชื่อจากผู้ใช้,
การแยก sessions, train/export/load ด้วยข้อมูลสังเคราะห์ และการหยุดเมื่อโมเดลปฏิเสธ
ข้อมูลสังเคราะห์มีไว้ตรวจเส้นทางซอฟต์แวร์เท่านั้น ไม่ใช่โมเดลท่ามือที่ส่งให้ใช้งาน
ยังไม่มีข้อมูลมือจริงของคุณ จึงยังไม่ได้สร้างโมเดลใช้งานหรืออ้างความแม่นยำจริง

[scikit-learn MLPClassifier](https://scikit-learn.org/stable/modules/generated/sklearn.neural_network.MLPClassifier.html)
